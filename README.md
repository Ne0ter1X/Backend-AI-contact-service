# Backend AI Contact Service

Backend-сервис формы обратной связи для лендинга разработчика, реализованный на **FastAPI**.

Проект выполнен в рамках тестового задания и демонстрирует разработку REST API, слоистую архитектуру приложения, интеграцию AI, обработку ошибок, логирование и организацию backend-проекта.

---

# Реализованный функционал

## REST API

### POST `/api/contact`

Принимает данные формы обратной связи:

* имя;
* email;
* телефон;
* комментарий.

После получения запроса:

1. выполняется валидация входных данных;
2. проверяется ограничение по количеству запросов (Rate Limiting);
3. анализируется тональность комментария с помощью AI;
4. сохраняется статистика обращений;
5. отправляется письмо владельцу сайта;
6. пользователю отправляется письмо-подтверждение;
7. возвращается результат обработки.

---

### GET `/api/health`

Проверка доступности сервиса.

Пример ответа:

```json
{
    "status": "ok"
}
```

# Реализация API

## POST /api/contact

### Пример запроса

```json
{
    "name": "Иван Иванов",
    "email": "ivan@example.com",
    "phone": "+79991234567",
    "comment": "Хотел бы обсудить сотрудничество."
}
```

### Пример успешного ответа

```json
{
    "message": "Success",
    "sentiment": "positive"
}
```

### Возможные HTTP-коды

| Код | Описание                  |
| --- | ------------------------- |
| 200 | Запрос успешно обработан  |
| 400 | Некорректный запрос       |
| 422 | Ошибка валидации          |
| 429 | Превышен лимит запросов   |
| 500 | Внутренняя ошибка сервера |

---

# Валидация

Для проверки входящих данных используется **Pydantic**.

Проверяются:

* имя;
* email;
* телефон;
* комментарий.

При некорректных данных FastAPI автоматически возвращает ошибку **422 Validation Error**.

---

# AI-интеграция

Для анализа пользовательского сообщения используется OpenAI API.

На текущий момент реализован анализ тональности комментария.

Возможные результаты:

* positive
* neutral
* negative
* unknown

Если AI-сервис недоступен:

* запрос не прерывается;
* обработка продолжается;
* используется значение `"unknown"`.

Таким образом реализован механизм **Graceful Fallback**, требуемый тестовым заданием.

---

# Используемый промпт

Системный промпт:

> Return only one word: positive, neutral or negative.

Пользовательский промпт:

> Текст комментария пользователя.

---

# Отправка email

После успешной обработки формы:

* владельцу сайта отправляется письмо с данными обращения;
* пользователю отправляется письмо-подтверждение.

Для отправки используется SMTP.

---

# Логирование

Логируются:

* все входящие запросы;
* ошибки приложения;
* результаты обработки.

Логи сохраняются в файл.

---

# Rate Limiting

Для защиты от спама реализовано файловое ограничение количества запросов.

Для каждого IP хранится история обращений.

При превышении лимита API возвращает:

```http
429 Too Many Requests
```

---

# Хранение данных

В проекте не используется база данных.

Для тестового задания применено файловое хранение.

Используются JSON-файлы для:

* статистики обращений;
* Rate Limiting.

Логи сохраняются отдельно.

---

# Dependency Injection

Для уменьшения связанности компонентов используется простая реализация Dependency Injection.

Все основные сервисы создаются один раз и передаются в `ContactService`, что позволяет:

* уменьшить связанность между компонентами;
* упростить замену реализаций;
* облегчить тестирование;
* разделить ответственность между слоями приложения.

# Запуск проекта

## 1. Клонирование репозитория

```bash
git clone https://github.com/Ne0ter1X/Backend-AI-contact-service.git
```

## 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

## 3. Создание файла `.env`

Пример:

```env
OPENAI_API_KEY=your_api_key

SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=example@gmail.com
SMTP_PASSWORD=password

FROM_EMAIL=example@gmail.com
OWNER_EMAIL=owner@example.com

RATE_LIMIT_REQUESTS=5
RATE_LIMIT_WINDOW=60
```

## 4. Запуск приложения

Файл `main.py` расположен в директории `app`:

```bash
uvicorn app.main:app --reload
```
